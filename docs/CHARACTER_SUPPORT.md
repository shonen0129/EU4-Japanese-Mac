# 常用漢字・ひらがな・カタカナの対応

2.1.0では、常用漢字2,136字と、全角の基本ひらがな・カタカナ、関連記号を対象に日本語拡張を追加しました。実ゲームの入力・描画・セーブでの確認が必要な試験版です。

## 対象

- 常用漢字: Unicode 18.0.0のUnihan `kJoyoKanji=2010` にある2,136字。
- ひらがな: U+3041〜U+3096、U+3099〜U+309E。濁音・半濁音・小書き・繰返し記号を含みます。
- カタカナ: U+30A1〜U+30FE。濁音・半濁音・小書き・長音・中黒・繰返し記号を含みます。
- 関連記号: 漢字の繰返し記号・句読点・括弧など。

対象は重複を除いて2,337字です。[全字の一覧](SUPPORTED_CHARACTERS.tsv) を同梱しました。半角カナ・人名用漢字全体・常用外の拡張漢字・異体字セレクタ・絵文字の全対応を保証する仕様にはしていません。

常用漢字の出典: [Unicode UnihanのkJoyoKanji](https://www.unicode.org/reports/tr38/#kJoyoKanji)、[文化庁の説明](https://www.bunka.go.jp/prmagazine/rensai/kotoba/kotoba_009.html)。抽出元のUnihan.zipのSHA256は `4c93ea9c1f636451729a840978f1667a53886af37ba854fdcce109721c63d43e` です。データの許諾条件は [UNICODE-LICENSE.txt](UNICODE-LICENSE.txt) を参照してください。

## 「𠮟」の扱い

常用漢字にも4バイト文字の「𠮟」（U+20B9F）が1字含まれています。既存の16ビットの描画経路を利用するため、入力時に内部予約番号U+E000へ可逆変換し、逆変換時にU+20B9Fへ戻します。フォントのU+E000には「𠮟」そのものの字形を追加します。「叱」（U+53F1）は別の文字として保持し、代用しません。

既存の3バイトの内部エスケープと同じ形になるため、元のb5の描画・文字移動処理を使う構成です。ゲーム固有の全入力欄・保存経路での実証は残ります。U+E000はこの構成の予約番号で、通常の入力文字としては対象外です。

「𠮟」を使った名前を含むセーブでは、同じ日本語拡張とフォント補完を有効にしてください。元の公式b5や拡張を含まない他の環境とのセーブ互換性は保証していません。

## フォント補完

Main 1 Release 24の通常12書体には、常用漢字の「剝・塡・頰・𠮟」と、かな・濁点等の一部が不足していました。大きな見出し用の書体にはさらに不足がありました。

インストーラはMain 1のフォント定義とDDS画像を作業領域へ読み取り、Macの日本語フォントをCoreTextで描画して不足分を追加します。13書体のうち12書体には各13字、見出し用の1書体には112字を追加します。既存の字形の定義と、画像のベースレベル全画素を保持し、画像末尾へ追加領域を設けます。ミップマップを持つ書体ではミップマップも再生成します。

追加字形の字幅と位置は、既存の「日」の実寸を基準に合わせます。名目のフォントサイズをそのまま使用して文字が大きくなる問題を避けています。元と追加分で字体の細部が異なる場合があります。

生成物は補訳MODの `gfx/fonts/` に配置します。元のMain 1 ZIPとゲームのフォントファイルは編集しません。実行可能な他作者のバイナリ、システムフォント本体、生成済みのフォント画像を配布ZIPへ同梱する構成ではありません。

## 導入と更新

1. 通常版インストーラのメニュー1で導入します。旧版から更新する場合も1です。
2. 公式eu4dll_macの最新版をAPIで確認し、b5の配布物とソースZIPをSHA256で検証します。
3. 監査済みコミット `2d8bf60a7036630e8fab1e622d26e7f7bbe9948d` を基準に、内蔵の改修を適用して日本語専用dylibをローカルビルドします。未監査の上流タグは安全のため停止します。
4. 内蔵のフォント生成コードもApple Command Line Toolsでビルドし、対象字形を補完します。
5. 既存のバックアップ・作業用app・注入・署名検証・ロールバックの手順で配置します。
6. LauncherでMain 1・Main 2・Translation Supplementを同じplaysetで有効化します。言語はEnglishです。

CMake・Python・Homebrewは不要です。初回のビルド後は、ソース・コンパイラ・生成物のハッシュで検証したローカルキャッシュを再利用します。SIP・Gatekeeper全体の設定は変更しません。

日本語拡張の導入後、メニュー7ではappを変更せず、本文・UI・フォント補完を再生成できます。メニュー8で補訳を削除すると、フォント補完も削除されます。別のフォントMODが同じファイルを上書きすると補完が適用されないため、標準の3MODで確認してください。

## 実施した検査と限界

- 対象2,337字すべてについて、文字変換→逆変換の一致をarm64とRosetta上のx86_64のASan付きハーネスで確認。
- 「𠮟」と「叱」、「剝」と「剥」等を混ぜた文字列を区別し、ファイルへの書き出し・読込でも一致することを確認。これは変換ハーネスのファイル試験であり、EU4のセーブ試験ではありません。
- 分解された「か＋濁点」「は＋半濁点」「う＋濁点」等はNFCで合成し、「が・ぱ・ゔ・ヴ」として往復することを確認。
- 元のb5で見つかった短い特殊文字列のバッファ不足は、今回の変換コードを可変長文字列へ置き換えて対処。長い入力と不完全なエスケープもASanで検査。
- 13書体すべてで対象番号が存在し、追加字形に画素があり、既存の定義・元画像のベースレベル全画素が一致することを確認。DDSの寸法・サイズ・ミップマップも照合。
- 隔離appで、ソースの取得・ローカルビルド・x86_64・注入・署名・配置・診断・削除・再導入・異常時停止を検査。

Intel実機、実ゲームの全画面・日本語IME・植民地命名・セーブ／ロードは未検証です。実際のゲーム・Launcher設定・ユーザーのセーブは変更していません。

実機ではテスト用の新規キャンペーンを使い、「新京都・がぱゔヴ・𠮟剝塡頰」を入力して、確定・左右移動・途中挿入・削除・再表示・保存・ロード後の名称を確認してください。既存キャンペーンの互換性確認は別途必要です。

## 2.2.0の配布方式

ネイティブ部分は管理リポジトリに同梱したソースからビルドします。上流ソースZIPや配布バイナリを実行時に取得する以前の方式は使いません。日本語MODはdependencies.lock.jsonの承認済み版・SHA256に固定しています。現在の手順はルートREADMEとSECURITY.mdを参照してください。
