# 不具合監査と2.0.1の修正

監査日: 2026-11-15。2.0.0のインストーラ／補訳生成処理と公式eu4dll_mac b5の監査を記録した資料です。インストーラ側の5項目は2.0.1で修正しました。

**2.1.0の追記:** 常用漢字・かなへ対象を絞った日本語専用のローカルビルドを追加しました。以下の短い特殊文字列のバッファ不足はこの改修版で対処し、常用漢字「𠮟」は可逆な内部番号で対応しました。他の絵文字・拡張漢字の完全対応は行っていません。公式配布b5自体の修正ではありません。詳細は [CHARACTER_SUPPORT.md](CHARACTER_SUPPORT.md) を参照してください。

## 公式b5に確認した問題（監査記録）

### P1: 短い特殊文字列のUTF-8変換でバッファ不足

`escapedStrToUtf8` と `escapedStrToUtf8Val` は入力バイト数の2倍だけを確保します。一方、CP1252の一部文字はUTF-8で3バイトになり、末尾のNULにも1バイト必要です。入力が1バイトの左二重引用符（内部値0x93）なら、確保2バイトに対して4バイトを書き込みます。

b5の変換本体を変更せず単体ハーネスに組み込み、`escapedStrToUtf8Replace` を呼ぶとAddressSanitizerが `heap-buffer-overflow` を検出しました。短い文字列でのクラッシュやメモリ破損の原因になり得ます。セーブ名のフックからもこの変換が使われています。実ゲームでのクラッシュ再現は未実施です。

出典: [b5 strConvert.cpp 272行](https://github.com/PoXiao-zero/eu4dll_mac/blob/b5/src/strConvert.cpp#L272)、[b5 saveFileName.cpp 26行](https://github.com/PoXiao-zero/eu4dll_mac/blob/b5/src/saveFileName.cpp#L26)。

対応には上流側で出力容量と終端を含む境界検査を修正し、x86_64のdylibを再ビルドする必要があります。インストーラ／翻訳文の変更だけでは解消しません。2.1.0ではこのために改修したソースをローカルビルドします。

### P2: 4バイトUTF-8文字が `????` へ置換される

`UTF8ToWindows1252` は絵文字や一部の拡張漢字などの4バイト文字を、明示的に4個の疑問符へ変換しています。単体テストでも絵文字1文字から `????` への変換を確認しました。「𠮷」のようなBMP外の漢字も同じ分岐を通ります。

したがって、これらを含む植民地名やセーブ名の文字化けはb5では解決できません。通常の漢字・ひらがな・カタカナ・中黒を含む `新京都・日本語かなカナ` は変換→逆変換が一致しました。これは変換関数の検査結果で、macOS日本語IMEとEU4の入力欄全体の動作保証にはなりません。

同じ4バイト分岐には他の分岐にある出力上限検査もありません。出力領域を32,768バイトとした単体呼び出しで、長い絵文字列による範囲外書き込みも検出しました。通常のSDL入力イベントでこの長さが渡ることは確認していません。

出典: [b5 strConvert.cpp 91行](https://github.com/PoXiao-zero/eu4dll_mac/blob/b5/src/strConvert.cpp#L91)。

### 静的候補: カーソル位置と関数ポインタの防御不足

入力コードはカーソル位置を使う前に `0 <= index <= length` を一貫して検査していません。右移動処理では符号なしの長さから符号付きの位置を減算するため、位置が長さを超えると差が大きな正数へ回り込み、範囲外の文字を読み得ます。実際のゲームで不正なカーソル位置になる条件は未確認です。

Backspaceとカーソル位置取得用の `dlsym` 戻り値にもNULL検査がありません。ただし、この環境のSteam版EU4 1.37.5.0を読み取り専用で調べた結果、入力処理に必要な7シンボルはすべて存在し、5個の検索パターンはいずれも1件ずつ一致しました。この環境で関数欠落が発生している証拠はありません。

出典: [b5 input.cpp 139行](https://github.com/PoXiao-zero/eu4dll_mac/blob/b5/src/input.cpp#L139)、[右移動と初期化](https://github.com/PoXiao-zero/eu4dll_mac/blob/b5/src/input.cpp#L302)。

## 検証範囲

既存の38件のインストーラ単体検査、5,416件の全文言・GUI検査に加え、今回14件の回帰単体検査を実施しました。公式ZIPを使った隔離appの導入・更新・失敗23ケース、補訳生成9項目、中断復旧4項目を再実行し、今回の監査用ネイティブ検証5項目も追加しています。最終結果は [VERIFICATION.txt](VERIFICATION.txt) を参照してください。

実物のEU4には読み取り専用のシンボル／パターン検査のみを行いました。ユーザーのゲーム、Launcher設定、playset、セーブを変更していません。文字変換のASan検査はb5ソースから作成した独立ハーネスであり、公式配布dylibをASan付きでゲーム内実行した結果ではありません。変換ハーネスはarm64とRosetta上のx86_64の両方で同じ結果を確認しました。Intel実機での検査は未実施です。

## 日本語命名の実機確認

1. テスト用の新規キャンペーンで、Main 1・Main 2・補訳だけを有効化し、言語をEnglishにします。
2. 植民地命名で `新京都` を入力し、IME変換中のBackspace、確定後の左右移動、文字の途中への挿入・削除を確認します。
3. 確定した名称を閉じて再表示し、保存してロードした後も同じ名称になることを確認します。
4. セーブ名でも通常の漢字・かなを使い、新規保存・上書き・読込・削除を確認します。
5. 問題があれば、入力した文字、変換中／確定後のどちらで崩れるか、使用IME、EU4版、インストーラの「診断のみ」の結果を記録します。

上流の修正版が出た際は、その版のソース・SHA256・実ゲームでの再検証が必要です。2.0.1の修正はインストーラと補訳生成処理が対象で、2.1.0では対象文字の変換とフォントを追加改修していますが、ゲーム内の動作確認は残ります。

## 2.1.1 追加修正

国名の末尾英数字へのバイト混入、国名の境界検査、字間調整後の文字列による容量計算、地図フックの書き込み失敗時停止、国名非表示の診断モードを実装。[MAP_SAFETY.md](MAP_SAFETY.md) に詳細と残る課題を記載。実ゲームでのクラッシュ解消は未確認。

## 2.1.2 署名検証の修正

実プレイ後に残る `Contents/MacOS/console_history.txt` による署名検証失敗を再現。作業用appの履歴をapp外へSHA256・サイズ照合付きで保管してから署名するよう修正。履歴本文はログに出さず、既存の保管データを削除・無検証で上書きしない。[SIGNING_FIX.md](SIGNING_FIX.md) を参照。

## 2.2.0の配布方式

ネイティブ部分は管理リポジトリに同梱したソースからビルドします。上流ソースZIPや配布バイナリを実行時に取得する以前の方式は使いません。日本語MODはdependencies.lock.jsonの承認済み版・SHA256に固定しています。現在の手順はルートREADMEとSECURITY.mdを参照してください。
