# 2.1.2: console_history.txt による署名検証失敗の修正

今回のエラーは、EU4が作成した `Contents/MacOS/console_history.txt` がコード用ディレクトリに残っていたためです。`codesign` の署名処理自体が成功しても、その後の厳密な検証で、この履歴ファイルが未署名として扱われました。[Appleの署名ディレクトリ規則](https://developer.apple.com/library/archive/technotes/tn2206/)も参照してください。

これはダウンロード・チェックサム・dylib注入の失敗ではありません。2.1.1ではこの生成済みファイルを扱えていませんでした。失敗した処理は `preparing` 段階で復元されているため、新しいdylibの適用は完了していません。

## 変更内容

2.1.2では署名前に、作業用app内のこの履歴ファイルだけを、次の場所へ保管します。

```text
~/Library/Application Support/EU4-Japanese-Mac/
  preserved-runtime-files/console-history/<SHA256>.txt
```

- コピー後のSHA256とサイズが一致してから、作業用app内のコピーを取り除きます。
- 既存の実appは、署名検証と切り替えが成功するまで元のまま残ります。切り替え後の失敗でも、元の履歴を含むappへ戻ります。
- 同じ内容は同じ保管ファイルを再利用し、違う内容は別ファイルとして残します。既存の保管ファイルの内容がハッシュ名と一致しなければ、上書きせず停止します。
- 履歴本文はログへ出しません。ファイルのSHA256と保管先だけを記録します。
- アンインストール時も同じ処理を行い、保管済み履歴は削除しません。Steamのapp外に保管するため、ゲーム本体の置換から独立して残ります。

履歴はゲームが再作成する場合があるため、次回更新時にも同じ処理を行います。ゲーム内のコマンド履歴は新規に作られることがありますが、以前の内容は上記の場所に残ります。セーブやSteam Cloudのデータは移動・削除しません。

任意のテキストファイルをまとめて移動する実装ではありません。他の未対応ファイルで署名に失敗した場合は、そのエラーを維持して停止します。署名検証を省略・緩和する変更は行っていません。

## 確認した項目

元の配置での署名失敗、退避後の厳密な署名検証、同一内容の再利用、複数世代の保持、保管先の内容不一致、コピー失敗、シンボリックリンクの拒否、実appへの直接実行の拒否を検証しています。導入・更新・切り替え後の失敗時の復元・アンインストールの検証記録は `VERIFICATION.txt` を参照してください。

2.1.1の国名描画の修正と診断モードはそのまま含まれます。国名処理の実ゲームでのクラッシュ解消を、この署名問題の修正だけで保証するものではありません。
